# MVP 产品范围

## 1. 产品定义

Finance Data Thinking MVP 是一个面向研究人员、财务分析人员和具备基础财务知识的个人用户的证据驱动型财报分析 Agent。用户上传一家上市公司的年度报告后，系统提取核心财务事实、执行确定性指标计算、识别财务风险，并生成能够回溯到原始报告页码和表格行的分析报告。

系统提供研究辅助，不执行交易、资金划转、账户操作，也不输出保证收益或无条件买卖指令。

## 2. 冻结的首期场景

### 2.1 目标用户任务

> 上传一家 A 股非金融类上市公司的中文年度报告，选择报告期，获得包含三张财务报表摘要、15 项核心指标、风险提示、数据限制和逐项证据引用的分析报告。

### 2.2 输入

- 一份用户主动上传的年度报告 PDF。
- 公司名称与证券代码；系统可提取，但用户必须能够确认或修正。
- 报告期，例如 `2025-12-31`。
- 分析截止时间 `as_of`，默认取任务创建时间。
- 可选关注点：盈利质量、现金流、偿债能力或综合分析。

### 2.3 输出

- 公司、报告期、币种、金额单位和合并口径确认结果。
- 资产负债表、利润表和现金流量表的核心事实。
- 15 项核心财务指标及公式、输入值和计算结果。
- 盈利能力、增长质量、现金流和偿债能力分析。
- 结构化风险清单：严重程度、判断依据、证据和限制。
- 一份区分事实、计算、推断和风险提示的报告。
- 每个重大数字和重大结论对应的来源文件、页码、章节或表格行。
- 独立 Evaluator 的验收结果和未通过原因。

## 3. MVP 支持边界

### 3.1 支持

- A 股非金融类上市公司。
- 中文、可检索文本的正式年度报告 PDF。
- 合并财务报表；人民币为主要记账币种。
- 单家公司、单个年度报告、单次分析运行。
- 报告中同时存在本期与上期可比数据。
- 用户上传文件，不依赖首期外部数据供应商。
- 中断恢复、运行追踪、证据查看和独立验收。

### 3.2 暂不支持

- 银行、保险、券商及其他采用特殊报表结构的金融机构。
- 扫描件 OCR、图片型 PDF 和严重损坏或加密的文件。
- 季报、半年报、招股书、债券募集说明书。
- 实时行情、新闻、宏观数据或多数据源自动交叉抓取。
- 多公司横向比较、投资组合分析和估值预测。
- 多 Agent 团队、MCP 动态工具、Cron 风险监控。
- 自动下单、撤单、转账或券商账户连接。
- 个性化投资建议、目标价和收益承诺。

## 4. 首期核心指标

| 类别 | 指标 |
| --- | --- |
| 增长 | 营业收入增长率、净利润增长率 |
| 盈利 | 毛利率、净利率、ROA、ROE |
| 杠杆与偿债 | 资产负债率、流动比率、速动比率、利息保障倍数、现金短债比 |
| 现金流 | 经营现金流/净利润、自由现金流 |
| 经营质量 | 应收账款增长率、存货增长率 |

指标必须由确定性计算模块产生。LLM 只能解释计算结果，不得自行重算或改写数值。

## 5. 标准用户流程

1. 用户上传年度报告并填写或确认公司与报告期。
2. 系统校验文件格式、可解析性、报告类型和公司身份。
3. 系统创建 `AnalysisRun` 和任务图，返回 `run_id`。
4. 系统提取三张报表的核心字段并保留证据定位。
5. 系统完成单位、币种、期间和合并口径标准化。
6. 确定性计算模块生成指标和计算轨迹。
7. Agent 基于事实、指标和证据生成风险判断与报告草稿。
8. 独立 Evaluator 校验完整性、计算、证据、表达和合规。
9. 验收通过后发布报告；未通过则将结构化反馈路由到对应节点修订。
10. 系统保存报告、证据包、评测结果、日志和恢复点。

## 6. 完成定义

一次分析只有同时满足以下条件才能进入 `verified`：

1. 公司、证券代码、报告期、币种、金额单位和合并口径已确定。
2. 三张财务报表的必需字段已提取，缺失字段有明确原因。
3. 所有计算指标均保留公式版本、输入事实 ID、结果和异常状态。
4. 重大数字结论的证据覆盖率为 100%。
5. 所有高严重度风险判断至少包含一个直接证据和一个计算或规则依据。
6. 报告区分事实、计算结果、模型推断和限制。
7. 不存在编造来源、无依据数字、收益保证或无条件买卖指令。
8. 独立 Evaluator 的必需检查全部通过。
9. 工作流 Journal、Checkpoint、报告和证据包已持久化。

执行 Agent 只能提出 `candidate_complete`，无权自行设置 `verified`。

## 7. 质量目标

| 维度 | MVP 目标 |
| --- | --- |
| 关键事实证据覆盖率 | 100% |
| 重大结论证据覆盖率 | 100% |
| 黄金集必需事实提取准确率 | 不低于 98% |
| 确定性指标计算通过率 | 100% |
| 严重合规违规 | 0 |
| Checkpoint 恢复成功率 | 100%（黄金流程） |
| 重复请求幂等性 | 同一幂等键只产生一个运行 |

金额勾稽容差不写死为统一货币值，而是依据报告披露单位计算：默认允许一个披露单位的舍入误差。比率比较默认允许 `0.01` 个百分点的显示舍入误差。

## 8. 失败与人工确认

以下情况必须失败或暂停，不得猜测：

- 文件不是年度报告、无法解析、加密或主要内容为扫描图片。
- 公司身份、报告期、币种、单位或合并口径存在无法消除的冲突。
- 关键事实在同一报告内出现不可解释的不一致。
- 证据不足以支持重大结论。
- 用户要求执行交易、规避权限、隐藏风险或输出保证性结论。

以下情况需要用户确认后继续：

- 系统提取的公司或报告期与用户输入不一致。
- 同一指标存在多个合理口径且会显著改变结论。
- 用户要求导出可能包含敏感信息的材料。

## 9. 约束与假设

- 首期以用户上传 PDF 为唯一正式事实来源，避免数据授权和实时性依赖。
- 原始文件不可变；所有派生数据必须引用原始文件哈希。
- 模型输出不是事实来源；事实只能来自原始文档或确定性计算。
- 所有时间相关对象必须保存 `as_of`、`created_at` 和来源发布时间（如可获得）。
- 所有任务和工具调用必须携带 `run_id`、`task_id` 和 `trace_id`。

## 10. MVP 退出条件

满足以下条件后，才进入实时数据、多公司比较或多 Agent 阶段：

- 至少 10 份真实年度报告完成双人复核并进入黄金集。
- 黄金集端到端评测达到本文件质量目标。
- 所有阻断级缺陷关闭，核心流程无未解释的随机失败。
- 数据模型、证据模型和指标定义连续两个迭代无破坏性变更。
- 能从任意持久化节点恢复，并生成相同的确定性指标结果。
