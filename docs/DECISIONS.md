# 设计决策

> 记录会影响产品边界、架构、数据口径、模型、工具权限或合规策略的重要选择。每条只说明：做了什么、为什么、何时做、替代方案和约束。

## 2026-09-04：定位为辅助决策 Agent，不执行交易

- 决策：项目提供金融研究、数据分析、风险提示和报告能力；不执行下单、资金划转、账户操作或权限变更。
- 原因：首期应优先验证分析结论的质量、可追溯性和合规性，避免将 Agent 直接置于高影响金融操作链路。
- 否决方案：直接接入券商或交易接口并由 Agent 自动执行操作。
- 约束：涉及具体投资动作时，只能提供条件化分析、风险提示和人工复核入口。

## 2026-09-04：以文件和 Git 检查点作为跨会话事实来源

- 决策：使用 `PROGRESS.md`、本文件、`VALIDATION.md` 与 Git 状态保存可交接工作状态，不依赖聊天记录。
- 原因：Agent 会话短期记忆可能丢失；结构化记录能让后续会话快速恢复上下文并审计关键选择。
- 否决方案：仅依赖聊天历史、长提示词或单一任务看板恢复上下文。
- 约束：暂停、交接或完成可验证单元前，必须更新对应记录；记录只写已验证的项目事实。

## 2026-09-04：以 Make 命令作为统一会话初始化 harness

- 决策：每次会话以 `make setup && make test` 建立可运行环境并验证基线；上班、下班流程写入 `AGENTS.md`。
- 原因：统一入口可减少不同 Agent 的环境差异，并让会话开始与结束时的状态检查可重复执行。
- 否决方案：依赖每位 Agent 自行判断初始化命令，或新增尚未维护的独立 `init.sh`。
- 约束：环境或测试命令发生变化时，必须同步更新 `AGENTS.md`；基线失败需要先记录，不能默默忽略。

## 2026-09-04：以原子 Git 提交作为可恢复检查点

- 决策：每完成一个可验证的原子工作单元即创建 Git 提交，提交信息说明改动内容和动机。
- 原因：Git 提供低成本、可审计、可回溯的状态快照，可避免跨会话混淆未完成或无关改动。
- 否决方案：只在功能全部完成后提交，或将多个无关改动混入同一提交。
- 约束：提交前检查 diff；不提交密钥、敏感数据、构建产物或无关变更。

## 2026-09-04：首期聚焦用户上传的非金融类 A 股年度报告

- 决策：MVP 只处理用户上传的中文、可检索文本、合并口径年度报告，并排除银行、保险和券商。
- 原因：单一稳定输入能先验证三表提取、确定性计算、证据链和独立验收，避免实时数据授权、OCR 和特殊行业口径同时增加风险。
- 否决方案：第一版同时接入实时行情、新闻、多个市场和金融行业报表。
- 约束：扫描件、季报、多公司比较、多 Agent、MCP 和自动监控延后；变更范围必须先更新 `PRODUCT_SCOPE.md`。

## 2026-09-04：金融事实、计算结果和模型结论分层存储

- 决策：使用 `FinancialFact` 保存来源事实，`CalculatedMetric` 保存确定性计算，`Claim` 保存原子结论，`Evidence` 建立可追溯关联。
- 原因：混合存储会导致模型文本被误当成事实，也无法复算或定位错误来源。
- 否决方案：只保存最终报告，或允许 LLM 直接写入已验证事实和指标。
- 约束：重大数字和结论证据覆盖率必须为 100%；只有 Goal Gate 可以将运行设置为 `verified`。

## 2026-09-04：先用合成黄金用例建立 CI 基线

- 决策：建立正常盈利、利润与现金流承压、单位与零分母边界三个合成黄金用例；真实财报必须双人复核后才进入产品准确率评测。
- 原因：合成数据可立即稳定公式和契约测试，同时避免把未经核验的模型输出或公开报告解析结果误称为黄金答案。
- 否决方案：直接下载若干真实财报并把首次模型输出当作预期结果。
- 约束：合成数据只用于 CI，不用于证明真实 PDF 解析准确率；真实数据必须登记来源、哈希、授权、页码和复核记录。

## 2026-09-04：使用 uv 锁定 Python 环境并保留双平台入口

- 决策：Python 3.12 依赖由 `pyproject.toml` 和 `uv.lock` 管理；Linux/CI 使用 Make，Windows 使用等价的 `scripts/dev.ps1`。
- 原因：uv 提供快速、可重复的锁文件安装；双平台入口让本地没有 Make 时仍能执行同一组质量门禁。
- 否决方案：只维护手工 `pip install` 步骤，或让 Windows 和 CI 执行不同的检查集合。
- 约束：两个入口的检查顺序必须保持一致；任何子命令失败必须立即返回非零状态，禁止继续并误报成功。

## 2026-09-04：分析运行初始化采用单事务持久化包

- 决策：创建请求在一个数据库事务中写入 `AnalysisRun`、根 `Task`、初始 `AuditEvent` 和 `WorkflowCheckpoint`；用户与幂等键组合由数据库唯一约束保护。
- 原因：运行记录、审计证据和恢复状态必须同时存在，不能让部分写入造成无法审计或无法恢复的运行。
- 否决方案：先返回 `run_id`，再由后台任务分别创建审计与 Checkpoint；只在应用内检查幂等而不建立数据库约束。
- 约束：唯一约束冲突必须回读原运行；其他完整性错误继续失败。当前暂用 `X-User-ID` 传递测试身份，接入认证前不得视为可信生产身份。

## 2026-09-04：以产品功能表作为唯一开发编号来源

- 决策：严格采用已确认的 F001–F018 产品功能表：F001 为项目初始化与健康检查，F002 为财报上传与文件存储；分析运行初始化属于内部支撑能力，不占产品 Feature 编号。
- 原因：开发功能、金融分析运行时任务具有不同生命周期。共用编号会让进度看板、数据库任务和验收证据产生错误映射。
- 否决方案：使用 `INFRA-001` 或让分析运行占用 F001，再维护额外映射表。
- 约束：`FEATURES.json` 是项目建设编号的唯一来源；运行时 `Task.feature_id` 使用 `CAP-*` 能力标识。历史 Git 提交信息保持不变，由本决策解释。

## 2026-09-04：物理对象与运行内来源记录分层去重

- 决策：`StoredObject` 以 SHA-256 作为全局内容地址并保存唯一物理对象；`SourceDocument` 以 `run_id + sha256` 唯一并引用该对象。
- 原因：同一份年报可能用于多个分析运行。全局复用字节可以避免重复存储，而运行内独立来源记录可以维持用户归属、审计和生命周期边界。
- 否决方案：将 `SourceDocument.sha256` 设为全局唯一；为每个运行复制一份相同 PDF；按原始文件名寻址。
- 约束：对象一旦存在只能校验和复用，禁止覆盖；哈希路径内容不一致时必须返回存储完整性错误。数据库失败产生的无引用对象只能由后续经过验证的安全清理流程处理。

## 2026-09-04：F002 只做输入可用性校验，不提前承担财报语义解析

- 决策：F002 校验 PDF 签名、媒体类型、大小、加密状态、页数和最低可检索文本量；公司、报告期、年报类型和逐页内容确认留给 F003 及请求校验节点。
- 原因：上传安全与文档语义解析是不同任务；混在 F002 会扩大任务边界并让完成证据不清晰。
- 否决方案：上传时直接让 LLM 判断公司、期间和报表内容，或接受图片型 PDF 后隐式调用 OCR。
- 约束：F002 的 `text_extractable=true` 只表示达到文本阈值，不代表财报身份已经确认；扫描件和加密文件必须返回可操作错误，不能自动切换未批准的外部服务。

## 2026-09-04：迁移同时接受轻量测试与 PostgreSQL 方言验证

- 决策：本地契约测试使用隔离 SQLite 数据库；独立 CI 必须在 PostgreSQL 17 上执行 `alembic upgrade head` 和 `alembic check`。
- 原因：SQLite 能快速验证业务事务和空库升级，PostgreSQL CI 能捕获生产方言、约束和驱动差异。
- 否决方案：只依赖 ORM `create_all`，或只在 SQLite 上声明迁移完成。
- 约束：迁移与 ORM 元数据出现漂移时门禁失败；生产数据库 URL 只注入迁移步骤，不能污染独立单元测试。

## 2026-09-06：F003 使用页级真值与不可变坐标索引分层

- 决策：`DocumentPage` 保存原始页码、页面文本、文本哈希、解析器版本和结构化结果；文本块与表格候选坐标保存为规范 JSON 不可变对象，并由 URI 与 SHA-256 回引。解析只使用本地确定性 pypdf，不调用 LLM、OCR 或外部服务。
- 原因：金融结论必须能回到原 PDF 页和局部区域，同时避免把大型坐标结构复制到工作流 State 或将模型判断混入来源事实。不可变边车索引既可复核又能被后续 Evidence 定位复用。
- 否决方案：只保存整份 PDF 的纯文本；把坐标 JSON 直接塞入 LangGraph State；在 F003 让 LLM 判断三张报表；解析失败后自动切换外部 OCR。
- 约束：页码从 1 开始且必须覆盖原 PDF 全部页面；单页失败要保留稳定错误，不得丢弃其他页；坐标 bbox 是带版本的文本矩阵估算，表格区域仅为候选，F004 必须重新验证其财务语义。

## 2026-09-06：F004 以确定性规则保存三表识别结果与歧义候选

- 决策：新增 `StatementIdentification` 持久化实体和 `statement_extract` 接口；只在 F003 已解析页文本与不可变坐标索引上运行版本化规则，分别输出合并资产负债表、利润表和现金流量表的 `located`、`missing` 或 `ambiguous` 结果。
- 原因：三表识别必须能回到页码、标题、报告期和表格候选定位；母公司表、目录命中、多个候选和期间冲突不能被静默选择。
- 否决方案：让 LLM 直接选择表格、把识别结果塞入 `DocumentPage` JSON，或在 F004 顺便抽取字段、统一单位和计算指标。
- 约束：合并口径必须有明确标题标记；只有母公司候选只能产生缺失原因；无法消除的范围或期间歧义进入人工确认；F004 不创建 `FinancialFact`，不提前实现 F005 及后续功能。

## 2026-09-06：真实年报以官方候选加哈希封存和双人复核入集

- 决策：使用巨潮资讯网公开披露的 2024 年 A 股非金融公司年报全文作为候选来源，但只有实际取得、记录使用依据和 SHA-256、完成 Reviewer A/B 独立标注及冲突裁决后，才进入 F004 真实评测集。
- 原因：公开 URL 能提供可审计来源，但 URL 本身不能证明当前工作区文件未被替换、确为全文、可检索或三表口径已确认；双人复核是防止把首次解析结果当作真值的最低控制。
- 否决方案：直接把公开链接、搜索摘要或首次模型输出作为黄金答案；下载后不留哈希；由同一人同时标注和验收。
- 影响范围：`docs/F004_REAL_REPORT_REVIEW_PLAN.md`、F004 验证记录和后续真实集统计；不改变 F004 API，不启动 F005。
- 约束：候选、已准入、已复核、已裁决和已封存状态必须可区分；准确率声明必须引用样本清单、哈希、复核记录和可复算统计。

## 2026-09-06：真实样本试运行结果不得替代独立真值

- 决策：真实年报机器预标注只作为 Reviewer A/B 的候选材料；出现重复候选、合并/母公司口径不清或报告期冲突时，必须保留 `ambiguous/awaiting_user`，不能自动选定或把机器结果写成黄金标签。
- 原因：对 10 份真实报告的试运行显示候选数量显著高于 1，且至少出现 000651 现金流量表报告期被识别为 `2024-01-12` 的错误；直接统计会制造虚假的中文年报准确率。
- 否决方案：以候选数量最多的页为真值、由同一代理生成 A/B 两套标签、或为通过验收而静默修正报告期。
- 影响范围：`data/real_reports/machine_preannotations.json`、F004 真实集验证记录和后续复核工作；不改变 F005 及后续功能边界。
- 约束：必须先修正并重新验证规则，再由独立复核者对 30 个三表目标完成盲标和裁决；当前 F004 保持 `candidate_complete`。

## 2026-09-06：F004 对重复报表页采用可解释主表排序

- 决策：当同一报表类型出现多个候选时，保留全部候选，但依据完整标题、主表单位/编制单位、目标期间、续表标记、审计/附注上下文和五年摘要上下文进行版本化排序；仅唯一最高分且达到门槛的候选可定位，平分继续进入歧义。
- 原因：真实年报同时包含合并表、母公司表、审计报告提及、附注引用和五年摘要；简单按标题命中会产生候选爆炸。日期解析必须把“2024 年 1—12 月”视为年度期间而不是 2024-01-12。
- 否决方案：静默取第一页、取最后一页、删除重复候选，或把模型猜测写成唯一真值。
- 影响范围：F004 识别服务、真实样本机器回放和回归测试；不启动 F005。
- 约束：评分只决定机器候选优先级，不替代 Reviewer A/B 和 Goal Gate；所有候选及评分仍须可追溯。

## 2026-09-06：F005 先在隔离实验分支验证字段标准化契约

- 决策：在 F004 正式 Goal Gate 尚未完成期间，允许在 `codex/f005-experimental` 分支实现 F005 的工程契约，但不改变主线 Feature 状态或解除正式依赖。
- 原因：字段标准化可以先用合成/契约数据验证原始值、标准值、Decimal 换算、口径保留和冲突处理，同时避免把未复核真实年报写入黄金集。
- 否决方案：直接在主线把 F005 标为 `in_progress`；把机器预标注当作真实字段真值；提前实现 F006 指标计算。
- 影响范围：新增 `FinancialFact`、F005 迁移、确定性映射服务和隔离 API；不改变 F001–F004 识别逻辑，不声明真实中文年报准确率。
- 约束：实验结果必须可回滚；F004 仍需独立复核和 Goal Gate；正式合并前必须重跑 F004→F005 集成验收。

## 2026-09-06：增加透明的 provisional 工程推进状态

- 决策：在不改变 `verified` 含义和 Goal Gate 硬门禁的前提下，功能目录增加 `provisional` 状态；项目负责人可批准 F004 进入 `provisional`，并允许依赖链中的 F005 进入工程开发。
- 原因：独立开发者可以继续验证相邻工程契约，同时明确区分“可开发”与“正式验收/真实准确率已验证”。
- 否决方案：把 F004 直接改为 `verified`；删除 F004 依赖；用机器回放替代独立 Goal Gate。
- 影响范围：`FEATURES.json` 状态机、F004/F005 进度和 F005 工程启动；不改变 F001–F004 运行代码的事实语义，不解锁 F006。
- 约束：`provisional` 只允许 F004/F005 使用；真实中文年报准确率声明仍禁止；只有 Goal Gate 可以写入 `verified`；F005 只使用合成/契约数据直到正式验证。

## 2026-09-06：为 F005 注册可执行专项验证器

- 决策：将 `make verify-feature FEATURE=F005` 注册为真实门禁，执行 F005 专项测试、全量质量检查、SQLite 全量迁移和 Alembic 零漂移检查；Windows 使用 `scripts/dev.ps1 verify-feature -Feature F005` 等价入口。

## 2026-09-06：F004 只生成空白 A/B 盲审副本

- 决策：由 `prepare_f004_review.py` 校验封存 PDF 后生成 Reviewer A/B 两份空白 CSV；副本只保留目标身份字段，不复制机器预标注。
- 原因：需要降低人工复核的交付成本，同时保持 A/B 独立和机器结果盲化。
- 备选方案：由 Agent 直接填充 A/B 标签；否决，因为同一执行者不能伪造独立复核或黄金真值。
- 影响范围：只完成 F004 复核准备，不改变 F004 状态、不计算真实准确率；完成状态仍需真实复核者和裁决人提供证据。

## 2026-09-07：在独立复核完成前推进可用的 provisional 指标系统

- 决策：根据项目负责人要求，允许 F006 在 `provisional` 工程模式下实现并进入本地可用系统，但只使用合成或契约事实验证；F004/F005 的正式 `verified` 门禁、真实年报准确率限制和 Goal Gate 含义不变。

## 2026-09-07：F009 采用确定性财务分析规则并自动挂接证据

## 2026-09-07：F010 采用确定性风险规则和证据降级

- 影响范围：`RiskFinding` 模型、F010 迁移、确定性规则服务、风险 API、验证器和 F010 文档证据；不启动 F011，不改变 Goal Gate 的 `verified` 权限。

## 2026-09-07：F011 只读组装版本化候选报告

- 决策：F011 使用确定性报告组装器，从已持久化的 `FinancialFact`、`CalculatedMetric`、`Claim`、`Evidence` 和 `RiskFinding` 生成 `financial-report-v1` 的 `candidate` 报告；报告分区保存事实、计算、推断、风险、限制和证据映射。

## 2026-09-07：F013 由唯一 Goal Gate 写入终止状态

- 决策：F013 新增 `GoalGateDecision`，仅 Goal Gate 服务能在独立 Evaluation 全部必需检查通过且报告仍为 `candidate` 时，将报告和运行写入 `verified`；其他结果写入 `revision_required` 或 `blocked`，并保存修复节点、原因和证据引用。
