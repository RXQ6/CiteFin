# 黄金测试数据

## 1. 用途

该目录为财报解析、事实标准化、指标计算、风险识别、证据映射和端到端评测提供稳定基准。黄金数据是测试事实来源，不从模型回答自动生成，也不能因系统输出不同而反向修改预期答案。

## 2. 当前组成

首批数据是三份合成财报片段，用于在尚未获得真实报告双人复核结果前建立可运行基线：

- `G001_standard_profitable`：正常盈利、现金流健康的制造企业。
- `G002_profit_cashflow_stress`：收入、利润下降，经营现金流为负，应收和存货上升。
- `G003_unit_and_zero_denominator`：百万元披露单位、上期净利润为零、短期借款与利息费用为零。

合成数据可以用于 CI 和公式验收，但不能用于宣称系统对真实年度报告已经达到产品准确率目标。

## 3. 目录结构

```text
tests/golden/
├── README.md
├── manifest.json
└── cases/<case_id>/
    ├── source.md
    └── expected.json
```

`source.md` 模拟分页财务报表文本。`expected.json` 保存用例元数据、应提取事实、预期指标、风险和证据定位。

## 4. 用例粒度

一个黄金用例代表：

> 一家公司 + 一份来源文档 + 一个报告期 + 一个固定分析截止时间。

用例 ID 是稳定主键。修改来源或预期答案时必须提升 `case_version` 并重新复核，不能覆盖历史含义。

## 5. 必做质量检查

### 完整性

- 公司、代码、报告期、币种、披露单位和合并口径存在。
- 所有指标需要的输入事实均存在，或明确测试缺失/零分母。
- 每个必需事实具有页码、报表、行名和列名。

### 唯一性

- `case_id` 在 manifest 中唯一。
- 事实粒度 `concept + period_end + period_type + scope` 唯一。
- 指标代码在单个期间内唯一。

### 有效性

- 百分比结果以小数保存。
- 金额事实同时保存披露值和换算到元的标准化值。
- `null` 指标必须具有 `status` 和 `reason`。

### 一致性

- 资产=负债+权益。
- 毛利润=收入-营业成本。
- 指标输入引用的概念必须存在。
- 风险引用的指标或事实必须存在。

### 时效性

- 报告期和来源公开时间不得晚于 `as_of`。
- 真实报告发生更正时，旧用例保留，新建版本。

## 6. 数值比较

- JSON 中十进制预期值使用字符串，避免二进制浮点误差。
- 比率内部值为小数，例如 `0.20` 表示 20%。
- 金额标准化为元。
- 金额勾稽默认允许一个披露单位的舍入误差。
- 比率展示比较允许 `0.01` 个百分点的舍入误差；计算层应使用未四舍五入值。

## 7. 真实年度报告进入黄金集

真实 PDF 只有满足以下条件才可将 `eligible_for_product_accuracy` 设为 `true`：

1. 来源公开且使用符合授权和项目数据政策。
2. 记录原始下载地址、公开时间、文件 SHA-256 和页数。
3. 一名标注者完成事实、指标、风险和证据定位。
4. 第二名复核者独立检查关键事实与全部重大结论。
5. 分歧已解决，并在复核记录中保留原因。
6. 财务报表勾稽和指标复算全部通过。
7. 不包含未脱敏的用户数据或账户信息。

建议首批真实集覆盖：制造业、软件服务、零售、周期行业和亏损企业，每类至少两份报告。银行、保险和券商不进入 MVP 黄金集。

## 8. 变更纪律

- 修正黄金答案必须说明原答案为何错误，并更新验证记录。
- 不得为了让测试通过而降低证据要求或删除失败用例。
- 模型、提示或解析器升级后，先运行全部黄金集，再决定是否接受变更。
